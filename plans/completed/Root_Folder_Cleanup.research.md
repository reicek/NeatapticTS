# Root Folder Cleanup — Step 02 Research Artifact

## Question

Which root-level files and directories in `C:\NeatapticTS` are temporal, debug,
snapshot, script, or documentation artifacts that should be **deleted**,
**relocated**, or **kept** during the root-folder cleanup? For every candidate,
what is the evidence and the canonical destination path (for relocations)?

## Evidence Methodology

1. Listed every non-hidden root item.
2. Checked `.gitignore` to determine which items are already treated as
   generated/ignored output.
3. Read `package.json` to confirm whether any candidate is referenced from
   build/test/lint scripts.
4. Ran a broad, recursive `Select-String` reference search across `src/`,
   `testing/`, `benchmarks/`, `examples/`, `scripts/`, `plans/`, and `docs/`
   for each candidate and its basename.
5. Inspected the remaining ambiguous items directly (root docs, root browser test
   pages, `files/mcp-facade/`, `bench-browser/`, `ascii_maze_snapshots/`,
   debug scripts, and coverage audit scripts).
6. Verified index health with the `cortex-index` gate; it reports the workflow
   MCP as not alive for this plan, so native reads/grep were used as the
   fallback search path.

## Decision

- **Delete**: all `tmp*` files and `tmp/`, `artifacts/`, `freshness-proof-BGe1HE/`,
  `ascii_maze_snapshots/`, `missing-semantic-index.sqlite`, `coverage/`,
  `lcov-parse.cjs`, `verify-results.mjs`, `coverage_audit*.mjs`, `debug-*.mjs`,
  `regex-test.cjs`, `check-*.mjs`, `smoke-*.mjs`, and the legacy root browser
  HTML/worker pages.
- **Relocate**: `bench-browser/` → `testing/browser-benchmarks/` (or
  `benchmarks/browser/` as a lower-churn alternative); `Browser_Tests.md`,
  `WebGPU.md`, `ONNX_EXPORT.md`, and `WebGPU_architecture/` → under `docs/`
  per the plan’s canonical destinations; `files/mcp-facade/` →
  `scripts/agent-customization/mcp/facade-contract/` after merging duplicate
  snapshots and updating the lazy-facade test paths.
- **Keep**: standard project files (`README.md`, `CONTRIBUTING.md`, `LICENSE`,
  `STYLEGUIDE.md`, package files, config files), core source trees, `data/`,
  `nn.jpg`, and build-output directories as out-of-scope.

## Risks

1. **`docs/` is broadly gitignored** (`/docs/*`, unignoring only
   `docs/research/` and `docs/research/README.md`). Relocating tracked
   documentation into `docs/` may make the files untracked unless they are
   force-added or `.gitignore` is refined. This is a **Spec-Kit `contradicts`**
   finding between the plan’s canonical destination and the repo’s ignore rules.
2. **`ascii_maze_snapshots/` will recur**: the ASCII maze example hard-codes
   `./ascii_maze_snapshots` as its default persistence directory. Deleting the
   empty directory only cleans the current checkout; the next example run will
   recreate it unless the default is moved.
3. **`bench-browser/` is load-bearing for benchmarks**: two benchmark test files
   import or build from `bench-browser/`. Relocation must include updating those
   paths.
4. **`files/mcp-facade/` is load-bearing for MCP facade tests**: the
   lazy-facade red tests read the two tool snapshots from this directory.
   Relocation/deletion must update test paths before the root directory is
   removed.
5. **Workflow MCP / plan-format mismatch**: `scripts/agent-customization/mcp/mcp-plan-utils.mjs`
   expects a top-level `## Implementation phases` heading, but
   `plans/Root_Folder_Cleanup.plans.md` uses `## Phase 1 — Root folder cleanup [WIP]`
   directly. This prevents `neataptic-workflow-mcp-get_slice_context` from
   loading the plan context and will block RAG-based dispatch for Step 03 unless
   the plan is reformatted or the parser is relaxed.
